# Internal application contract

All arrays are copied/validated at public solver boundaries; use NumPy float64 and zero-based blade indices internally. File ownership during parallel work: backend owns rotor_math.py, solver.py, test_solver.py, test_rotor_math.py; data owns data_io.py and test_data_io.py; UI owns gui.py, main.py and test_gui.py. Parent owns docs, requirements, benchmark and integration. Do not change another owner's files without agreement. No git commits/push/PR/release by children.

## rotor_math.py

- `RotorInputs` frozen dataclass: `mode: str = 'blade_only'` (only 'blade_only' or 'combined'), `diameter_mm: float = 500.0`, `thickness_mm: float = 50.0`, `density_kg_m3: float = 7850.0`, `cg_radius_mm: float | None = None`, `cg_offset_mm: float = 0.0`, `runout_mm: tuple[float, ...] = (0.0,)*8`.
- `HarmonicFit` frozen dataclass: `ex_mm, ey_mm, mean_mm, residual_rms_mm: float`, `fitted_mm: tuple[float,...]`. `first_harmonic(runout_mm) -> HarmonicFit`.
- `RotorModel` frozen dataclass: `mode: str`, `ex_mm, ey_mm, disk_mass_g, disk_ux_gmm, disk_uy_gmm, radius_mm, runout_mean_mm, runout_residual_rms_mm: float`, `runout_fit_mm: tuple[float,...]`, `warnings: tuple[str,...]`.
- `build_rotor(inputs: RotorInputs) -> RotorModel`; blade_only ignores inactive thickness/density/runout inputs, sets e/disk/mass to zero. radius explicit cg_radius_mm overrides diameter/offset; otherwise D/2+offset. Physical finite positive active dimensions, e < nominal CG radius; do not silently infer mass eccentricity as measured.
- `SlotGeometry` frozen dataclass: arrays `angles_rad, radii_mm, x_mm, y_mm`.
- `slot_geometry(n: int, rotor: RotorModel) -> SlotGeometry`, supports integer N=2..120 (explicitly reject bool/fraction/out of range); r=R+ex cos+ey sin. Angles 2*pi*arange(n)/n, zero at +x, CCW.

## solver.py (does not import GUI or data_io)

- `SolverConfig` frozen dataclass: `seed: int = 42`, `iterations: int = 100_000`, `restarts: int = 5`, `alpha: float = 0.9999`, `initial_temperature: float | None = None`, `trace_every: int = 250`. Limits validation needed.
- `SolverResult` frozen dataclass fields: `permutation: tuple[int,...]`; `initial_ux_gmm, initial_uy_gmm` (NET initial), `initial_blade_ux_gmm, initial_blade_uy_gmm`, `greedy_j_gmm, pairing_j_gmm, initial_j_gmm, residual_gmm, blade_ux_gmm, blade_uy_gmm, net_ux_gmm, net_uy_gmm, lower_bound_gmm, elapsed_ms: float`; `iterations_completed: int` total swaps across starts; `seed: int`; `method: str`; `trace: tuple[tuple[int,float],...]` total proposal index / globally best J; `warnings: tuple[str,...]`.
- `vector_sum(masses, permutation, x_mm, y_mm, disk=(0.0,0.0)) -> tuple[float,float]` independent accurate full sum, validates permutation.
- `swap_delta(masses, permutation, x_mm, y_mm, a, b) -> tuple[float,float]` O(1) arithmetic, usable tests.
- `vector_greedy(masses, x_mm, y_mm, disk=(0.0,0.0)) -> tuple[int,...]` exact requested descending-mass running-vector construction.
- `greedy_pairing(masses, x_mm, y_mm, disk=(0.0,0.0)) -> tuple[int,...]` deterministic heavy/light opposite or nearest opposite odd heuristic; describe algorithm.
- `solve(masses, x_mm, y_mm, disk=(0.0,0.0), config=None, method='hybrid', cancel=None) -> SolverResult`. `method` 'hybrid' or 'pairing'. Hybrid always retains best of original/vector greedy/pairing then runs all requested starts (first exact vector greedy, others deterministic randomized/perturbed). Run full default 500,000 proposals even if residual tiny; no false guarantee. Pairing method returns pure pairing result, can be worse than original and clearly labelled. `cancel` optional threading.Event or callable; raise `SolverCancelled` exception when cancelled, never present partial as complete.
- `warm_up() -> float` milliseconds for JIT warmup; useful GUI startup, excluded from warmed solver benchmark but reported separately. Use Numba nogil cache, no wall-clock truncation. If cancellation checked between blocks, blocks should be <=2048 swaps. Full sums periodic not per proposed swap; verify final independent full sum.

## data_io.py

- `Blade` frozen dataclass `blade_name: str`, `weight: float` (g).
- `validate_blades(blades) -> tuple[Blade,...]`, N=2..120, names nonempty unique, masses finite positive. No normalization of source IDs beyond validation that strip is nonempty; preserve exact nonempty name.
- `read_blades_csv(path) -> tuple[Blade,...]`, UTF-8 BOM accepted; comma or semicolon delimiter; required exact headers blade_name and weight, may allow weight_g alias only if clearly documented; blank/missing/nonnumeric/nonfinite/zero/negative weights actionable errors with row. Duplicate headers/IDs rejected. Preserve exact IDs. Transactional no GUI side effects.
- `sample_blades(n=32, seed=42) -> tuple[Blade,...]`, deterministic rounded mass g ~100 +/- few grams, no use of original literature moment values as masses.
- `export_schedule_csv(path, blades, permutation, angles_rad, *, metadata=None, overwrite=False) -> None`. Columns exact `slot_number,angle_deg,blade_name,weight_g`; 1..N and degree angles. Full schema/permutation validation before writing. Use exclusive create unless overwrite=True explicit consent, atomic replace via sibling temp for overwrite. Spreadsheet injection guard for blade IDs beginning =,+,-,@ or leading control/whitespace before these, plus preserve safe identifiers exactly; document reversible leading apostrophe escaping. Validate against path existing dir, partial writes; no silent overwrites. metadata optional dictionary if omitted keep compatible simple schedule; parent can add sidecar separately.

## gui.py and main.py

- `MainWindow()` QMainWindow. - `set_blades(blades)` validated transactional populate/update N; `get_blades()` validated table -> tuple[Blade,...]; `import_csv_path(path)` raises ValueError/OSError on invalid with original table/result retained; `export_csv_path(path, overwrite=False)` raises when no current valid result, uses current solved snapshot, never stale inputs; `start_optimization()` asynchronously, `show_result(result, blades, rotor, geometry)` renders completed verified result; `invalidate_results()` clears result, results table, plots/metrics and disables export on ANY edited input (including mode/method/seed). Snapshot active inputs and prevent edits or revision check while running.
- Disable thickness/density/runout in blade_only, leave nominal CG radius active. Radius may use auto toggle D/2+offset, otherwise explicit. Persistent orange safety banner for combined mode and consistent reference/CCW/units.
- Worker thread performs warm_up and solve; cancellation and close safely managed, no QThread destruction while running; state/error restoration tested. No GUI updates from worker. Working thread should not freeze UI during JIT. Show busy state, final solve duration and compile separately.
- Modern readable engineering workbench: branded header, compact config panel, blade table, results cards. Dashboard 4 readable plots if possible: vector polar (all four vectors with legend listing magnitude and phase and zero phase 'undefined'), slot map/weights, measured vs1x runout, SA best-so-far convergence. Embedded matplotlib canvas with toolbar. Separate mounting schedule tab and engineering help tab. Matplotlib aspect and text must be visually verified by real screenshots. Slot table noneditable. No 'balanced/certified' green pass claims or false near-zero guarantee.
- `main.py` real runnable entry point. Optional `--demo` populates sample combined case; optional `--screenshot PATH` or separate parent script may capture Qt window using QWidget.grab() to avoid desktop occlusion. Normal launch shouldn't silently calculate over unknown data.
- Tests with pytest-qt run offscreen, cover both modes, button/table workflow, import errors, export, stale-result invalidation, worker error/cancellation. All new behaviours follow RED→GREEN vertical TDD with real command output recorded; do not write all implementation first.
